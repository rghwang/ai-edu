04 · 조건문

길이 갈라지는 곳

let hp = 30; if (hp > 50) { console.log("아직 쌩쌩하다"); } else if (hp > 0) { console.log("위험하다"); } else { console.log("쓰러졌다"); }
읽는 순서는 위에서 아래로, 맞는 걸 만나면 멈춘다. 밑에 더 맞는 게 있어도 안 본다.
제일 헷갈리는 것

= 하나와 == 둘은
완전히 다르다

= 하나

이름표를 붙인다

hp = 0 → hp를 0으로 만든다. 조건문 안에 쓰면 체력을 0으로 만들어 버린다.

=== 셋

같은지 물어본다

hp === 0 → hp가 0이냐고 묻는다. 답은 true 아니면 false.

JS에서는 === 를 쓴다. 1부에서 본 "3" + 4 처럼, == 는 글자와 숫자를 멋대로 맞춰줘서 헷갈린다.
예측하고 실행

이 코드는
뭐라고 출력할까

let score = 85; if (score > 90) { console.log("A"); } else if (score > 80) { console.log("B"); } else if (score > 70) { console.log("C"); }
종이에 먼저 적는다. 그다음 — 순서를 거꾸로 뒤집으면 어떻게 되나? C가 먼저 오면?
고장 내기 3

조건을 부숴본다

  • else 를 통째로 지운다 — 아무것도 출력되지 않는 hp 값이 생기나?
  • > 를 >= 로 바꾼다 — hp가 정확히 50일 때 답이 달라지나?
  • 조건 순서를 뒤집는다 — 위아래를 바꾸면 왜 다 “위험하다”가 되나?
  • if (hp = 0) 로 바꾼다 — 체력이 어떻게 되나? 이게 그 유명한 실수다
04번은 에러도 안 난다. 조용히 틀리는 코드가 제일 무섭다.
05 · 반복문

같은 길을
여러 번 지나간다

for (let i = 1; i <= 5; i = i + 1) { console.log(i + "번째 몬스터 등장"); }
괄호 안에 세 가지가 들어 있다 — 어디서 시작(i = 1), 언제까지(i <= 5), 한 바퀴 돌 때마다 뭘 할지(i = i + 1).
이 셋을 따로 떼어 읽는 게 전부다.
값 추적표 · 반복문판

한 바퀴에
한 줄씩 적는다

바퀴 i i <= 5 ? 출력 1 1 참 1번째 몬스터 등장 2 2 참 2번째 몬스터 등장 3 3 참 3번째 몬스터 등장 4 4 참 4번째 몬스터 등장 5 5 참 5번째 몬스터 등장 6 6 거짓 (멈춤)
마지막 줄이 중요하다. 6번째 바퀴는 돌지 않지만 i는 6이 된다. 이걸 놓쳐서 하나가 모자라거나 남는다.
고장 내기 4

무한루프를
일부러 만들어 본다

해볼 것

i = i + 1 을 지운다

i가 영원히 1이면 i <= 5 는 계속 참이다. 브라우저가 멈춘다.

알게 되는 것

멈추는 이유가 있어야 한다

반복문은 “언제 끝나는지”가 몸통보다 중요하다. 먼저 그걸 확인한다.

겁내지 말고 해본다 — 탭을 닫으면 된다. 한 번 겪으면 평생 안 잊는다.
1부와 만나는 곳

나머지 % 가
여기서 쓰인다

for (let i = 1; i <= 10; i = i + 1) { if (i % 2 === 0) { console.log(i + " 짝수"); } else { console.log(i + " 홀수"); } }
반복문 안에 조건문이 들어갔다. 표를 그리면 열이 하나 늘어날 뿐이다 — i % 2 칸.
06 · 함수

같은 일에
이름을 붙인다

function damage(attack, defense) { let result = (attack - defense) * 2; return result; } console.log( damage(12, 5) ); console.log( damage(30, 10) );
1부의 데미지 계산을 이름 하나로 묶었다. 이제 숫자만 바꿔 여러 번 부른다.
함수 읽는 순서

정의는 건너뛰고
부르는 곳부터 읽는다

01
부르는 줄을 먼저 본다
damage(12, 5) — 12와 5를 들고 들어간다
02
이름표가 붙는다
attack에 12, defense에 5
03
몸통을 계산한다
(12 - 5) * 2 = 14
04
return 자리로 돌아온다
부른 자리가 14로 바뀐다
함수는 들어가고 나오는 것이다. 들어가는 건 괄호 안, 나오는 건 return.
고장 내기 5

return 을
지워본다

해볼 것

return result; 삭제

출력이 undefined 로 바뀐다. 계산은 했는데 아무것도 안 돌려준 것이다.

또 해볼 것

인자 순서 바꾸기

damage(5, 12) — 에러는 없는데 답이 이상하다. 순서에 뜻이 있다.

undefined 는 “없다”가 아니라 “돌려준 게 없다”는 뜻이다. 앞으로 자주 만난다.
내가 설명하고 채점받기

아래 코드와 내 설명이야. 코드 (코드 붙여넣기) 내 설명 반복문이 몇 번 도는지, 매 바퀴 i가 얼마인지, 언제 멈추는지를 내가 쓴 것 틀린 곳만 짚어줘. 고친 코드나 맞는 설명을 써주지는 마. 내가 한 바퀴를 잘못 세었다면 몇 번째 바퀴가 틀렸는지만 알려줘.
